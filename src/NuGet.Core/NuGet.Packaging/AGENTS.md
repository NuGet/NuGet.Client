# NuGet.Packaging

## Architecture & High-Risk Invariants

**Signature Verification is Async & Multi-Provider Chained**
- PackageSignatureVerifier chains multiple ISignatureVerificationProvider implementations (Integrity → Trust → AllowList)
- Final status is the **minimum** across all provider results: Unknown < Suspect < Disallowed < Valid
- Async chain completion must preserve order; provider failures propagate as SignatureException
- *Risk:* Non-obvious aggregation logic; status ordering reversed from semantic severity

**Signed Packages Lock Archive Immutability**
- SignedPackageArchive binds ZIP stream position and content hash to SignedPackageArchiveMetadata snapshot
- Signatures append to ZIP central directory; CRC32 validates unsigned content only
- Once signed, AddSignatureAsync() throws; RemoveSignatureAsync() clears and re-validates
- *Risk:* Stream disposal or position changes silently invalidate signature verification

**Multi-Framework Public API (perTfm Analysis)**
- UsePublicApiAnalyzer>perTfm enforces separate PublicAPI.{Shipped,Unshipped}.txt per TFM (net472, net8.0)
- Build fails if new public members omit Unshipped.txt entry
- Tools: 	ools-local/ship-public-apis moves Unshipped → Shipped
- *Risk:* TFM-specific overloads can masquerade as no API change

**Generated Resources (4 .resx → 40+ .xlf files)**
- Strings.Designer.cs, SR.Designer.cs, AnalysisResources.Designer.cs, NuGetResources.Designer.cs auto-generated from .resx
- XLF files checked into source; regenerated by build system. Do not hand-edit XML string values.
- *Risk:* Designer.cs edits lost on rebuild; localization sync breaks silently

**ContentModel Patterns Not Path-Based Selection**
- ManagedCodeConventions generates TFM/RID-aware PatternSet definitions
- Asset selection via property-ranked criteria matching, not simple directory scan
- "Best match" computed once; fallback chain is explicit per criteria builder
- *Risk:* Adding new asset types requires PatternTable updates; naive path logic will fail

## Test & Build Commands

**Unit Tests (net472 + net8.0):**
`
dotnet test test\NuGet.Core.Tests\NuGet.Packaging.Test\NuGet.Packaging.Test.csproj -c Release --filter "FullyQualifiedName~PackageArchiveReader|FullyQualifiedName~NuspecReader"
`

**Signing Verification (FuncTest with embedded .nupkg resources):**
`
dotnet test test\NuGet.Core.FuncTests\NuGet.Packaging.FuncTest\NuGet.Packaging.FuncTest.csproj -c Release --filter "Category=Signing"
`

**Build + API Validation:**
`
dotnet build src\NuGet.Core\NuGet.Packaging\NuGet.Packaging.csproj -c Release -v:m
`

**Pack (generates NuGet.Packaging.nupkg):**
`
dotnet pack src\NuGet.Core\NuGet.Packaging\NuGet.Packaging.csproj -c Release -o artifacts
`

## Critical Checklist

- [ ] No PublicAPI.{Shipped,Unshipped}.txt edits without matching public member addition
- [ ] Signature verification tests validate all three provider results (Integrity, Trust, AllowList)
- [ ] Signed package stream disposal does not proceed without explicit RemoveSignatureAsync() or close
- [ ] ContentModel additions update PatternTable and ManagedCodeConventions.Patterns
- [ ] Designer.cs files never edited; regenerated from .resx on build
